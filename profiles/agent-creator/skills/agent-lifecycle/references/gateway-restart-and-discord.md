# Gateway restart and Discord setup traps (checked on this Mac)

## Restarting the shared gateway (needs Robi's OK)
- `hermes -p default gateway restart` refuses while any session is live, including your own turn. Use `--yes` only when the refusal lists no session but your own chat's background job: it then interrupts only you (a short pause), never another helper's task. If anything else is listed, wait instead.
- Schedule it as a tracked background command: `sleep 40; hermes -p default gateway restart > <scratch>/restartN.log 2>&1` (terminal background=true, notify=true). Tell Robi to message you in about a minute, then END THE TURN with no more tool calls. Any tool call in that window keeps the turn live and the restart is refused (log says "Refusing to restart", the background job exits 1; the PID in `hermes gateway list` is unchanged and a helper test still shows the old tool set). Check the PID and its start time before every post-restart test: a test run against an unrestarted gateway looks like a helper fault ('cannot run in this configuration').
- Verify afterwards: new PID in `~/.hermes/gateway_state.json`, `<slug>:discord` state `connected`, and `hermes -p <slug> logs` shows "[Discord] Connected as ...". The background job's own log ending `EXIT 143` is expected: the restart ended the command that started it, so judge success by the PID and the connected state, not by that exit code.
- Moving a Discord bot to a new helper: one token lives in one profile only. After the new helper passes its tests, Robi resets the token and runs `gateway setup` for the new profile; the old helper's Discord goes quiet from then on.
- A helper added to MCP or a chat platform, or a changed `.env`, is only picked up after this restart. A bot that connected earlier keeps the OLD allowed users and channel settings until then. `-z` runs also go through the gateway, so a freshly added MCP tool looks missing until the restart.

## Discord setup with a newbie (one small step per message, wait for "done")
0. Scope the first Discord stage before any click: Robi asks the helper in a per-site channel and it answers there (still read-only). Digests, urgent alerts and yes/no approvals are separate later stages, each with its own approval. Ask whether to use an existing server or a new one.
1. Server: + > Create My Own > For me and my friends, then add the text channels.
2. Developer Portal > New Application > Bot: Public Bot OFF, turn on Server Members Intent and Message Content Intent, Save. If Save says "Private application cannot have a default authorization link": Installation tab > Install Link = None, then save the Bot page again.
3. Ask for the Application ID (not secret) and build the invite link yourself: `https://discord.com/oauth2/authorize?client_id=<ID>&scope=bot+applications.commands&permissions=309237763136` (no voice permissions).
4. Robi resets the token and runs `hermes -p <slug> gateway setup` himself. Never ask for the token.
5. Wizard prompts: "Allow yourself (@name) to talk to the bot? (Y/n)" is a real yes/no: tell him to answer Y (it saves his own ID; check the number afterwards against the one he copied). Wizard trap: "Other allowed users (comma-separated, Enter to skip)" is not yes/no. Robi typed `y` and it was saved as an allowed user. After setup read ONLY the allowlist line (`grep -E '^DISCORD_ALLOWED_USERS=' .env`), confirm the token exists with `grep -c '^DISCORD_BOT_TOKEN=.\+' .env` (never print it), fix with `sed -i ''`, and confirm permissions are still 600.
6. Allowed people are numeric user IDs (Developer Mode > right-click name > Copy User ID). Ask who each ID belongs to; never assume names from an email or screenshot (the team was wrongly written as Shachar and Precios and had to be corrected through an updated brief).
7. A channel where the helper answers without an @mention: `DISCORD_FREE_RESPONSE_CHANNELS=<channel id>` in the helper's `.env`. Other channels need an @mention. Tell Robi not to `/sethome` in a chat channel (home channel is for timer output).
8. `create_agent.py --update` keeps `mcp_servers` and `.env` (it rewrites only model, cwd and disabled toolsets). Re-verify after anyway.
9. The helper has no Discord posting tool unless one is set up (the log shows `check_discord_tool_requirements` false). Its instructions must not promise channel posts it cannot make; say so to Robi.
