# Apify prospecting and lead-funnel helper (lessons from the COB SDR build)

Use when Robi wants a helper to find leads with Apify, scrape LinkedIn or a members directory, or turn a scraped list into qualified leads.

## 1. Apify connection (checked against docs.apify.com/mcp)
- Hosted server https://mcp.apify.com. Catalog tools `search-actors` and `fetch-actor-details` work with NO login if the `tools=` URL parameter lists only those. Any run or storage tool needs a token (`Authorization: Bearer ${APIFY_TOKEN}` header, value in the helper's own `.env`, never in config).
- Run tools: `call-actor`, `get-actor-run`, `get-dataset-items`, `abort-actor-run`. The include list cannot limit WHICH Actor runs, so the allowed-Actor list is a rule in the helper's instructions (say so plainly). The hard walls are Apify's monthly limit (Robi sets it in Billing, Limits) and `maxItems` / `maxTotalChargeUsd` in `callOptions`.
- Apify refuses `maxTotalChargeUsd` below $0.50. A $0.15 cap made the first run fail with nothing charged. Set the per-run cap to exactly 0.50 and hold the real cost down with `maxItems`.
- Proof of real use: query Apify, not the helper's self-report: `GET /v2/actor-runs?limit=5` and `/v2/home/hermes/limits` with the token (read it with `grep` inside `$(...)`, never print it). Tool calls in the helper's `state.db` are named `mcp__apify__call_actor` (underscores).
- Config edit that worked: load `config.yaml` with yaml, set `mcp_servers.apify` (url, headers, tools.include), dump back. Check `mcp list`, `mcp test apify`, and that the token string is not in config.yaml. `create_agent.py --update` kept the `mcp_servers` block.
- A new MCP connection is seen only after a gateway restart. `hermes -p default gateway restart` refuses while any session is live (including this chat); `--yes` interrupts it. Run it as a background job with `sleep 20` first; exit code 143 is only the restart killing the launching shell. Confirm a new PID with `hermes gateway list`.

## 2. Token handling with a newbie
- Robi runs this in his own Terminal: `bash -c 'read -s -p "Paste the Apify token, then press Enter: " T; echo; printf "APIFY_TOKEN=%s\n" "$T" >> ~/.hermes/profiles/<slug>/.env; echo saved'`.
- After 'saved', never read the value. Check only: permissions 600, count of non-empty lines, length, prefix `apify_api_`, characters only letters, digits, underscore, and one read-only call (`/v2/home/hermes/^APIFY_TOKEN=/d'`, re-confirm, and have him create a fresh token and paste once with Cmd+V. A real token was 46 characters.

## 3. Cost and spending rules that worked
- Order: catalog lookup first (free), Robi's own Apify account and limit set, token placed, one tiny run with his yes to the exact settings, then verify the run and cost on Apify.
- First run: 20 places cost $0.0802. A Google Maps list gave names and categories, not UAE intent (11 of 20 had no website). Intent comes from search, news and company announcements, so give the helper Google Search and Google News Actors for 'interest' and keep Maps for place lists.
- Named-person add-ons (lead enrichment, personal profiles, reviews) collect personal data and cost extra: keep them off with a fixed refusal phrase. Contact details a business publishes on its own website are a lighter case and can be allowed (section 6).

## 4. Terms and personal-data facts (read 2026-11-18, verify again before relying)
- LinkedIn User Agreement section 8.2 bans bots and scraping of profiles. In hiQ v. LinkedIn scraping public pages was not a crime, but a court enforced the terms as a contract breach and hiQ paid $500,000. Using Apify does not change that. Robi decided to use LinkedIn anyway: record it as his decision with the risk, company pages only, no personal profiles, no login or session cookie (a personal account can be banned), no emails.
- BNI Terms of Service section 4 (effective 12 Oct 2026): no copying compiled member data for commercial use; scraping without written consent means paying BNI's legal costs. BNI also bans spam. No Apify Actor for BNI exists. Allowed shape: find people who say publicly (own site, news, posts) that they are BNI members; never open bni.com, BNI Connect or member pages (`-site:bni.com`). BNI people in Cherry's mailbox were referral partners, a separate motion.
- A scraped list of named people is personal data: keep only what the public source shows, keep it in files only while small, and move a large list and any nurturing into the CRM (RIBO) with opt-outs and a lawful basis.

## 5. Funnel design Robi chose (volume, then qualify, then nurture)
- Pilot first (50 leads), then report yield and cost per screened-in lead before scaling. Quick screen (real business, dated UAE-interest source, named decision-maker) before the full five tests. Qualified needs all five Met; financial readiness is never Met on size alone.
- Tests that passed: fixed phrases for refused actions ('That Actor is not approved.', 'I cannot turn on the lead enrichment add-ons.'), a made-up fully qualifying company and a made-up near-miss company, and plan-only runs in test mode. Poland-style 'later stage' tests can show REVIEW on a full stop in the phrase; that is test wording, not a fault.

## 6. Five-Actor funnel and the contact-data split (what Robi approved)
- Approved Actor list, each named by id in the helper's instruction (any other gets 'That Actor is not approved.'): `compass/crawler-google-places` (places), `apify/google-search-scraper` and `lhotanova/google-news-scraper` (intent, dated), `harvestapi/linkedin-company-posts` (posts on company pages), `michael.g/email-verifier-validator` (deliverability of emails a business published). Same caps for all: `maxItems` at most 50, `maxTotalChargeUsd` exactly 0.50, his yes in chat per run, live price re-read before each run.
- Contact split he accepted after a plain recommendation: ON = emails and phones a business publishes on its own website (Google Maps contacts option) plus the verifier. OFF = named-person lead enrichment (CEO names, verified emails), personal LinkedIn or social profile scrapers, reactions and commenter lists. Fixed phrases: 'I cannot turn on the lead enrichment add-ons.' and 'LinkedIn personal profiles are not approved.' When a rule is relaxed, grep the whole draft for the old phrase (instructions, examples, tests, plain words, requirements table) and change every copy, or an old test keeps expecting it.
- LinkedIn Actor choice: ask the helper (test mode, catalog only) for options that need NO login or cookie. Company-post Actors read a given company page; none searches LinkedIn for 'UAE', so the flow is Google Search or News for the company list, then the posts Actor on those company links, then filter posts for the target market. Prefer the cheapest widely used one (about $0.002 per post, 18k users), with reactions, comments and profile pages off and a 12-month date limit. Personal-profile Actors (`harvestapi/linkedin-profile-scraper`, employee finders) also try emails: refuse them.
- When Robi pastes several Apify use-case or Actor pages with no message, read every page and answer with one table (page, what it adds, fit). They are marketing examples of tasks with the paid add-ons switched ON; note any page whose header price and README price disagree (the Facebook and email-verifier pages did) and re-read the live price instead; drop off-profile pages (hotels, TikTok creators); then ask the single decision they imply (which contact data may be collected), with a recommendation.
- Updating the draft: edit a copy with a Python script that asserts each old string exists before replacing it (`patch` is fuzzy on long single lines), then count tests, run `--dry-run --update`, and measure the SOUL size. Each added Actor and phrase grew the instructions past 9,500 characters; offer the shortening pass right after the update.
